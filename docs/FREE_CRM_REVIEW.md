## Воронка и данные к проверке в кабинете

Стандартная сущность — сделка, связанная с существующим контактом. Создавать новый контакт на каждое новое обращение одного клиента нельзя. Новая заявка может потребовать отдельной сделки по принятой бизнес-правиле, но повтор того же запроса не должен создать две сделки; различать новый интерес клиента и повтор отправки. Проверить нормализацию телефона, поиск/сопоставление, параллельную отправку, тайм-аут после записи и полномочия с синтетикой. Если штатные настройки не обеспечивают нужное поведение, фиксировать блокер, а не обещать exactly-once.

Стадии по порядку: Новое обращение → Требует уточнения → Квалифицирован → Документы → Подбор финансирования → Передано кредитору → На рассмотрении → Выдача подтверждена → Комиссия получена; «Закрыто без выдачи» — отдельный конечный исход с причиной. Стадия не означает передачу файла или юридическое согласие. Управление переходами/обязательными полями и разграничение Owner/Manager необходимо проверить в бесплатном тарифе.

Источники: сайт, Telegram, WhatsApp, Instagram, звонок, партнёр, рекомендация, ручное добавление. Значение источника и UTM — отдельные контролируемые поля, без ПДн; значения/формат и обработка первых/повторных касаний утверждаются Owner. Подключение любого внешнего канала, его стоимость и маршруты данных — отдельные решения; токены никогда не помещаются в frontend. Сбор коммуникаций или загрузка отчётов по умолчанию отключены.

Поля для одной формы: услуга; сумма; срок (необязательно); имя; телефон; предпочтительный канал; комментарий (необязательно); обязательное отдельное согласие на обращение; отдельное добровольное согласие на рекламу. Тексты/версии/публичные URL и условия хранения подтверждения утверждаются Legal. Допустимость вставки стандартной формы без утраты основных CTA/дизайна и возможность получить надёжный success event от CRM — отдельно проверить. При отсутствии независимых согласий или достоверной записи версии/действия **не подключать форму для реальных заявок**.

## Метрика: проект, счётчика нет

Только после решения Owner/Legal и при наличии необходимого основания создать счётчик и согласовать cookie-уведомление. Вебвизор, аналитика форм и session replay выключены по умолчанию; [документация](https://yandex.ru/support/metrica/ru/webvisor/settings) указывает, что Вебвизор может записывать действия в полях. Не передавать ФИО, телефон, комментарий, PDF, значения полей, идентифицирующие UTM, URL или заголовки: [правила конфиденциальности](https://www.yandex.ru/support/metrica/en/general/confidential-data).

Предлагаемые константные цели без параметров ПДн: `service_click`, `form_open`, `form_start`, `lead_accepted`, `messenger_click`; просмотры — обычный счётчик после согласования. `lead_accepted` вызывается только после подтверждённого приёма CRM по документированному и проверенному событию; click/submit/iframe-load не являются таким подтверждением. Если vendor не предоставляет проверяемый callback, цель остаётся NOT IMPLEMENTED, не имитируется. URL и UTM должны проверяться отдельно до подключения счётчика; для UTM — только заранее одобренные неидентифицирующие значения и ограниченный срок хранения, никогда не вставлять произвольную строку пользователя в события. Показанные имена целей — проект конфигурации, не установленные цели.

## Размещение

GitHub Pages не принимается для коммерческого сбора; [ограничения GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits) относятся к хостингу онлайн-бизнеса и сайтов, ориентированных на коммерческие транзакции. Кандидат: статический frontend в [Yandex Object Storage](https://yandex.cloud/ru/docs/storage/operations/hosting/setup), без переноса дизайна в конструктор; обычные CRM-формы могут работать без собственного backend только после отдельной проверки поставщика. Для объекта public static site и его URL, HTTPS, собственного домена, логов и фактической географии нужен отдельный архитектурный проект: существующий `/api/leads` сам собой не появится.

[Тарифы](https://yandex.cloud/ru/docs/storage/pricing) указывают нетарифицируемые 1 ГБ стандартного хранения, 10 000 операций записи и 100 000 операций чтения в месяц; исходящий трафик и дополнительные сервисы учитываются отдельно. Это не обещание нулевого счёта: проверить HTTPS на собственном домене, DNS, CDN, трафик, биллинг/ограничения и применимые договоры. Ничего не покупалось и не разворачивалось.
