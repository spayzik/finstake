## 5. План синтетической проверки и свидетельства

Запускать только на явном test-контуре CRM с согласованными синтетическими контактами. Результаты хранить без секретов, OTP и реальных ПДн; каждое доказательство привязать к версии формы, тарифу, окружению и дате. Сохранить обезличенные desktop/mobile скриншоты интерфейса и результаты, а не подменять их скриншотами рекламного лендинга.

| Сценарий | Критерий принятия / статус |
|---|---|
| Desktop: заполнение и отправка | Реально получен подтверждённый ответ CRM, одна сделка + корректная связь с контактом; NOT RUN |
| Mobile: то же и клавиатура | Поля/checkbox доступны, подтверждение CRM и одна сделка; NOT RUN |
| Источник и UTM | Контролируемый `сайт` и разрешённые метки в карточке без ПДн; NOT RUN |
| Согласия | Без обязательного согласия нет записи; marketing отказ и согласие отдельно; версия/действие/время видны в доказательстве; NOT RUN |
| Повтор и два клиента/менеджера | Существующий контакт не дублируется, одна обработка того же запроса; новое обращение по согласованному правилу; NOT RUN |
| Сеть, задержка, неизвестный ответ | Ошибка видна без ложного success, повтор не создаёт дубль; не создавать заявку при offline; NOT RUN |
| Секреты frontend | Проверить bundle, карты, исходники и network; нет ключей/токенов; NOT RUN в интегрированном CRM build |
| Метрика | По network не уходят ПДн, success только после настоящего CRM ack, отсутствие Webvisor до допуска; NOT RUN |
| Owner/Manager | Два реальных отдельных аккаунта тестируют разрешённый/запрещённый доступ и уведомления; NOT RUN |
| Целевое размещение | HTTPS, карточки без кеширования ПДн, текущие CTA, rollback и скан потоков; NOT RUN |

`npm test` и `npm run build` выполняются на точном tree PR, без невошедших изменений Agent A; результаты/exit codes записываются в отчёт PR. После интеграции CRM, legal и аналитики требуется повторный полный E2E на точном принятом HEAD. Отсутствие скриншотов CRM или работающего аккаунта — не PASS.
